# [S] Drop the fork's per-method checksums

## Goal

Bindings generated by [the fork](/uniffi/README.md) load without calling a
checksum function per method, and the library no longer exports those
functions. The [binding benchmark](/quest/m1/ffi-bench.md) reports load time,
library size, and symbol count before and after.

## Plan

Decided with the maintainer on 2026-10-23: the fork's own contract namespace
already makes mixing with upstream UniFFI fail at load time, which is what the
checksums guard per method. Upstream can skip the check (`omit_checksums`) but
still compiles the functions in
([mozilla/uniffi-rs#2725](https://github.com/mozilla/uniffi-rs/issues/2725)).
Expect a small win; record the numbers either way.

Public API: none; generated bindings lose their checksum calls.

## Required

- [Waiting: the exporter decision](/quest/m1/ffi-export-decision.md) - paused until the maintainer decides whether this folds into the exporter, as the spike recommends
- [Namespaced FFI contract](/quest/m2/uniffi-contract.md) - what refuses a mismatched library once the checksums are gone
- [Binding benchmark](/quest/m1/ffi-bench.md) - load time, size, and symbol numbers
